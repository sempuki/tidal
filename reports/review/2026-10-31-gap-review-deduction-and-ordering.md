Role: source reader

Deduction page

M1. DED-P3 and DED-13. The table of positions that give no value lists only the part before a scope qualifier. In the reference, once a type name contains a position that gives no value, every template parameter anywhere inside that whole name gives no value too. A template parameter that appears only in a member template's argument list after the scope qualifier is therefore also not deduced. Probe: a function template whose only use of its second type parameter is as an argument of a member template named through a dependent class, called with the first parameter given explicitly. Expected: no viable function.

M2. DED-P3, DED-11. A template template parameter can take its value from a class template specialization whose arguments hold no template parameter at all, and also from a template template argument nested inside another specialization (a class template that takes a template, used as a function parameter type). The table only shows the template template parameter applied to a type parameter. Probe: a function parameter that is a holder of a template template parameter, called with a holder of a concrete class template. Expected: accepted, the parameter names that class template.

M3. DED-P3, DED-20. A function parameter pack written inside a function type (the parameter list of a function pointer parameter) takes each remaining parameter type of the argument's function type. No rule says so; DED-20 covers only packs among the call's own parameters. Probe: a template taking a pointer to a function whose parameters are a type pack, called with a function of two parameters. Expected: accepted, the pack has two elements.

M4. DED-P3. A pack expansion as the last argument of a class template specialization in a parameter type takes each remaining argument of the argument's specialization, one by one, and can take none. The page leaves packs aside, but this form is the most common use of deduction with packs and the ordering tests already depend on it. Probe: a parameter that is a tuple-like class of a type pack, called with an empty specialization and with a specialization of two types. Expected: both accepted, with zero and two elements.

M5. DED-24 and DED-P5. The reference also substitutes into the conditional explicit specifier of a constructor or conversion function template, and a failure there removes the template. The page lists only the function type and the template parameters. Probe: two constructor templates, one with a conditional explicit operand that is invalid for the argument type, the other plain. Expected: the plain one is used with no error.

M6. DED-29. The list of places outside the immediate context names class bodies and lambda bodies. The reference also counts the instantiation of a function template specialization (for example one whose result type must be deduced from its body), the implicit definition of special member functions, and similar side effects. Probe: a result type that calls a function template with a deduced result type whose body is invalid for the argument. Expected: hard error, not removal.

E1. DED-29. The reference treats a lambda expression in a template parameter declaration (for example in a default template argument) the same way as one in the function type: an error in its body is a hard error. The rule names only the function type. Probe: a default template argument that takes the size of a lambda whose body is invalid for the deduced type, with a variadic fallback overload. Expected: the program is not valid.

O1. DED-29. A generic lambda called inside the function type can fail its own deduction. That failure is a failed overload resolution for the call expression, so it stays in the immediate context and only removes the outer template. The rule could be read to make any problem tied to a lambda a hard error. Probe: a result type that calls a generic lambda whose trailing result type uses a member the argument lacks, with a fallback overload. Expected: the fallback is called and the program is valid.

O2. DED-28. In the reference the order is: substitute into the template parameter declarations and defaults, then check constraints, then check the parameters with no template parameter against their arguments, then substitute the function type. The rule says the check comes before substitution. The two orders differ when a default template argument instantiates a class with an error in its body. Probe: a template whose second template parameter defaults to a member type of a class template that errors in its body for the deduced type, whose first function parameter is a plain pointer type, called with an integer for that parameter, plus a fallback. Expected under the reference order: the program is not valid, because the default is substituted before the plain parameter is checked.

E2. DED-23. The rule makes only a trailing pack empty when it has no value. In the reference, any template parameter pack that gets no value is deduced as empty, wherever it sits in the template parameter list. Probe: a template whose head starts with a type pack, followed by a type parameter used as the only function parameter, called with one argument. Expected: accepted, with an empty pack.

E3. DED-20. The rule says a function parameter pack that is not last is empty unless explicit arguments fill it. In the reference such a pack is only a position that gives no value. Its template parameter pack can still get its elements from another position, for example a later parameter that is a tuple-like class of the same pack. Probe: a template whose first function parameter is a non-trailing pack and whose last parameter is a tuple-like class of the same type pack, called with two values and a matching tuple of two types. Expected: accepted.

E4. DED-15. In the reference the base class search is one of the allowed differences and runs only when the exact match fails. The rule does not say this, so a reader can apply the two-bases conflict even when the argument is itself a matching specialization. Probe: a recursive variadic class template where each specialization derives from the specialization with one fewer argument; pass a specialization of two types to a parameter that is a reference to that template of a type pack. Expected: accepted, the pack is the two types and the bases are not looked at.

O3. DED-15. The reference allows the derived class difference for any parameter written as a template name with arguments, which includes a template template parameter applied to arguments. The rule speaks of a class template specialization, which a reader may not apply to that form. Probe: a parameter that is a reference to a template template parameter applied to a type parameter, called with a plain class derived from a specialization of a known class template. Expected: accepted, both the template and the type are deduced from the base.

E5. DED-31. For conversion templates, the allowed differences go in the other direction from a call. The result type is the one that converts to the needed type, so the needed type may carry more qualification (qualification conversion from result to needed) and the needed type may lack noexcept where the result has it. The rule reuses DED-14, which describes an argument converting to a parameter. Also, when the needed type is a reference, the reference target may have more const or volatile than the deduced result; DED-31 does not list this case. Probe: a conversion template whose result is a pointer to a type parameter, used to initialize a pointer to const int; and one whose result is a reference to a type parameter, used to bind a reference to const int. Expected: both accepted, with the type parameter deduced as int.

O4. DED-30. The reference adjusts a forwarding reference matched against an lvalue reference only for parameters in the top level parameter list of the function type. A forwarding reference written inside a nested function type, such as a parameter of a function pointer parameter, gets no such adjustment. Probe: a template parameter that is a pointer to a function taking a forwarding reference, called with a function that takes an lvalue reference to int. Expected: no viable function.

M7. DED-32 and ORD-P1. The reference also uses deduction and partial ordering to find a placement deallocation function template that matches a placement allocation function in a new expression. No rule lists this context. Probe: a class with a placement allocation function and two placement deallocation function templates, one more specialized, and a constructor that throws. Expected: the more specialized deallocation template is chosen; with two unordered matches, no deallocation function is called.

M8. DED-24 and DED-2. After explicit arguments are substituted, the function type is adjusted before deduction runs. Two specializations whose explicit arguments differ only in top-level const have the same function type but are different functions. No rule states either fact. Probe: take the addresses of the specialization for int and for const int of a template with one by-value parameter and compare them. Expected: the addresses differ.

M9. DED-P3, DED-12. When a constant parameter declared with a placeholder type takes its value from an argument of a class template specialization, its type becomes the type of the class template's corresponding parameter. DED-11 states this only for the bound of an array. Probe: a function template with an auto constant parameter, called with a specialization of a class template whose constant parameter is long. Expected: the deduced constant has type long.

Ordering page

E6. ORD-6. In the reference, a member template with no ref-qualifier gets an rvalue reference object parameter when the matching first parameter of the other template is an rvalue reference. The rule always gives an lvalue reference in that case. The difference changes the result of ORD-10. Probe: a class with a member operator template with no ref-qualifier, taking a type parameter, and a non-member operator template whose first parameter is an rvalue reference to that class and whose second is a type parameter. Use the operator on a prvalue of the class. The sequences tie because of the rule for the implicit object parameter. Expected: ambiguous, since both object parameters are rvalue references and no tie-breaker applies.

S1. ORD-P2 and ORD-10. The reference applies the reference kind and qualification tie-breakers inside each type pair, as part of the per-pair "at least as specialized" result, before the two templates are compared overall. The diagram places them only in the branch where both directions succeed overall. The two models differ when one pair succeeds both ways and another pair succeeds only one way. Probe: one template takes a forwarding reference and a pointer to a type parameter; the other takes an lvalue reference to a type parameter and a plain type parameter. Call both with an int lvalue and an int pointer. Expected under the reference: ambiguous, since the first pair favours the lvalue reference template and the second pair favours the pointer template. The diagram instead gives the pointer template.

O5. ORD-10 and ORD-11. In the reference the qualification tie-breaker is used in a direction whenever the lvalue-over-rvalue condition does not fire in that direction, including when the argument side is an rvalue reference and the parameter side an lvalue reference. So an lvalue reference to a type parameter against an rvalue reference to const of a type parameter gives a demotion each way: no order. ORD-10 says the lvalue reference wins and ORD-11 only looks at references of one kind. Probe: such a pair in a context where the sequences tie, such as two conversion function templates with those result types or the member case of E6. Expected: neither is more specialized.

O6. ORD-12. The phrase "with no parameter against the pack" can be read as no call argument, or as no corresponding parameter in the other template. The reference means the second, and a parameter with a default argument counts as a corresponding parameter. Probe: one template with a type parameter and a second parameter of the same type with a default, another with a type parameter and a trailing type pack, called with one argument. Expected: ambiguous.

O7. ORD-13. The reference requires the template parameter lists and the full function parameter lists to have the same length before constraints are compared, and this includes parameters with default arguments that the call does not use. ORD-5 limits the compared types to those with arguments, so a reader can think a defaulted extra parameter does not matter. Probe: a more constrained template with an extra defaulted parameter against a less constrained template without it, called with one argument. Expected: ambiguous.

O8. ORD-13 and DED-34. The reference counts the type parameters invented for placeholder function parameters as part of the template parameter list for this comparison. Probe: a template with a placeholder parameter constrained by a stronger concept against a template with an explicit head whose one parameter is constrained by a weaker concept, same parameter type. Expected: the stronger one is chosen.

S2. ORD-13 and TPL-20. The condition uses head equivalence. In the reference, head equivalence also compares type constraints and requires clauses, while this condition compares only the template parameters themselves (kind, pack, type of constants, nested heads). Today TPL-20 leaves constraints out, so the two agree. Once constraints are specified, ORD-13 as written would never apply to templates whose constraints differ. Probe: two templates that differ only in the concept on their one type parameter, one concept subsuming the other. Expected: the subsuming one is chosen.

O9. ORD-3 and DED-13. The page does not say what partial ordering does with a position in the parameter template's type that gives no value (a member type through a dependent class, or a computed constant). The reference says a parameter used only there counts as used, so it needs a value, but it leaves open whether the non-deduced type must then match the argument type after substitution. Compilers are known to differ here. Probe: one template with a type parameter and a second parameter that is a dependent member type of an identity class of that parameter, against a template with two parameters of the same type parameter, called with two ints. Record the outcome per compiler; expect divergence and a question.

O10. ORD-4. The rule speaks of function parameters. The reference applies the same pack rules to the arguments of class template specializations inside the compared types: an invented pack expansion against a non-pack argument fails, and an invented pack expansion with no counterpart is ignored. Probe: three templates that take a tuple-like class of a type pack, of a type then a type pack, and of a type then a pack of lvalue references; call each with an empty tuple, with a tuple of int and float, with a tuple of int and a float reference, and with a tuple of one int. Expected: the first, the second, the third, and the third.

M10. ORD-P1. The list of contexts lacks the placement deallocation match of M7. The friend declaration and explicit instantiation cases are folded into "a declaration of a specialization", which is fine, but DED-32 and ORD-9 could say so with one list. Probe: see M7.

O11. ORD-7. In the reference the parameters are reversed only when exactly one of the two templates came from a reversed rewritten candidate. Reversing both gives the same pairs in another order, so the outcome is the same, but with the object parameter of ORD-6 inserted first the order of insertion and reversal matters. The rule does not say whether the object parameter is added before the reversal. Probe: a member comparison operator template and a non-member one, where only the member is used reversed. Expected: the member's object parameter ends up in the second position after reversal, and the result matches the non-member with swapped parameters.
