# Writer probes, roadmap round 11

Commit read: `3bd790ae`. The grids ran with `tools/probe_grid.py --errors`
on the baseline compilers (Clang 18, Clang 22 in its container and on
the host, GCC 14, GCC 16 in its container and on the host, EDG 7.0, and
EDG 7.0 ILP32), each run under `flock build/run_tests.lock`.
`writer-scratch/make_grids.py` writes the JSON files. Each `.out` file
holds the table and the first error of each compiler that rejects.

The probes compile only. A probe that needs a value puts it in a
`static_assert`, so EDG takes part.

| File | Finding | Result |
|---|---|---|
| `i6-call-binding.json`, `.out` | I6-1, I6-5, I6-9, I6-10, and I6-20: where a call in a template binds. Each row asserts the value that the overloads declared before the template give; a column adds a better overload after the template. A reject in that column means that the call saw the later overload. | Every compiler: an unqualified call whose arguments do not depend on the parameters finds `lib::probe` by argument-dependent lookup at the definition and does not see a later overload; with no declaration before the template, the call is rejected at the definition. A qualified call `lib::f(T{}, 0)` with a dependent argument does not see a later overload in `lib`. A call `f(T{}, 0)` where a member `f` is found does not see a later overload. The control, an unqualified call with a dependent argument, sees the later overload. `f(this->n, 0)` and `f(n, 0)` with a member `n` of type `lib::S` do not see the later overload on Clang 22, GCC, and EDG, also in a local class of a function template; Clang 18 alone sees it for the `this->n` forms. A specialization first used before the later overload and asserted after it: GCC 14 and 16 see the later overload; Clang and EDG do not. |
| `i6-instantiation-checks.json`, `.out` | I6-3, I6-7, I6-8, I6-13, I6-14, I6-16, I6-18. Each row defines `use<>()`; the second column calls it. The I6-6 and I6-15 rows of this grid are confounded, because `use<>()` names the class with arguments that do not depend on its parameter; `i6-6-15-clean.json` replaces them. | Every compiler rejects, before any instantiation, an undeclared name in a body (DEP-6), an unqualified name that only a dependent base declares (DEP-12), a template-id whose independent arguments fail the constraints (CNS-13), `C::value_type* q = nullptr;`, and `T::type value = 0;`. `int p = 0; T::x * p;` is accepted. `decltype(make())`, where `make` returns `Bad<int>` and `Bad<int>` fails when instantiated, is accepted; a call that passes `Bad<int>` by value is rejected. A friend function defined in a class template with a body that fails is accepted for an object with no call, and rejected when the program calls it. `typename T::template box b(1);` with no argument list: GCC and EDG accept, Clang 18 and 22 reject (Q-0226). |
