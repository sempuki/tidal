# 0044. Presenting a procedure

Date: 2026-10-31
Status: Accepted. Extends 0016 and 0033.

## Context

Items L, M, and O specify procedures: forming a conversion sequence,
choosing the best function, deducing template arguments. A procedure has
an order of steps and a list of tie-breakers. Tidal's rules are single
statements with tests, and its principles explain models. Neither form
says how to present an ordered procedure. The method controls on the
roadmap page ask for a test that only one tie-breaker decides, and for
Evidence that names each rule's source.

## Decision

A page that specifies a procedure has these parts:

| Part | Form | Holds |
|---|---|---|
| Principle | a plain-text diagram or a table | the steps in order, and the input and output of each step, with the rule ID of each step |
| One rule per step | `required` or `reject` | what the step does, and when the procedure stops with no result |
| One rule per tie-breaker | `required` | the case the tie-breaker decides. The rule says which tie-breakers come before it. |
| Probe grid tables | in Evidence, generated by `tools/probe_grid.py` | the outcome for every pair of categories, with the grid file committed under `tests/<page>/grids/` |

- A step or tie-breaker rule has at least one test that no other rule
  decides. The other rules give the same result for the two choices in
  that test, and the test's note says so.
- The order of the tie-breakers follows Tidal's principles. The order
  of a source text is not an input. Two tie-breakers that never decide
  the same case have no order, and the page says so.
- Evidence names the source of each rule. A source is a probe grid, a
  compiler diagnostic, a sanitized input, or an item of a source
  reader's inventory (by the inventory's own numbering).
- A gap review by a source reader follows the draft (decision 0019).

## Consequences

- `tools/probe_grid.py` compiles a grid of programs on the matrix and
  prints a table. A grid can cover every pair of its entries.
- Grid files are kept with the tests so that the tables can be
  regenerated. The runner collects only `*.cpp` files, so grid files do
  not run as tests.
- Items L, M, and O follow this form. Existing pages keep their form.
