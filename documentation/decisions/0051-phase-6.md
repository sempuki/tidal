# 0051. Phase 6: settle, cover by use, and check the object model

Date: 2026-11-01
Status: Provisional. Extends 0033, 0039, and 0050. All items are done.

## Context

Phases 1 to 5 are done. Five clean-room views ranked what comes next
(`reports/clean-room/roadmap-3/`): a programmer, an implementer, an
editor, a clean-room writer, and a language designer. They agree on
these points:

- No topic needs a new page. The cost now sits in repairs, open
  questions, and records that drift.
- Questions grow faster than they close. Phase 5 opened 51 and closed
  10. 289 are open, and 66 index rows say only "option 1".
- Readers have used most pages only through the front end. Two of
  fifteen Write suites have run. Predict and Diagnose batches have
  reached 22 of 85 pages, and their scores (1320 of 1323) no longer
  measure the text, because test names show outcomes.
- The status page and the question index hold numbers that no tool
  writes.
- The interpreter has no byte-level view of objects. It cannot run the
  storage page's tests or detect STG-23.
- No rule says that a program the grammar does not derive is rejected
  (Q-0312). The front end counts 127 parse stops as unsupported.
- Two *(class properties referenced)* markers still block the storage
  rules that use "trivially copyable" and "standard-layout".

## Decision

Phase 6 has these items, in this order. Items in one row can run in
parallel.

| Q | Settle the question backlog in clusters (housekeeping, overload tie-breakers, partial ordering, constant evaluation and undefined behavior, EDG alone on templates, template syntax), each followed by a source-reader gap review | editor, writer |
| G | The grammar-validity rule on `translation.md`. Extend decision 0042 to `undefined` rules, and add an expectation that only the interpreter checks for undefined runs that no sanitizer stops | implementer |

| P | Predict batches for the expressions, statements, declarations, and classes chapters, after R0 fixes the format | editor, implementer |
| D | The designer's repair batch (D3, D4, D6, D10, D11, D15, D25, D27, the two missing CE-P4 rows, the coroutine boundary note), then Propose round 3 (X9 to X12) | designer |

| O | Class properties: the trivially-copyable and standard-layout lists and per-target class layout, with method controls (a source-reader inventory, then probe grids) | all five |
| FE | Front-end round 10: byte-level memory, parse failures as rejects, interpreter coverage of finished pages, choice exploration and SEQ-4, the check-side gaps | implementer |

These choices hold until the maintainer decides otherwise:

- **Settling questions.** Where the newest version of each baseline
  family agrees with the provisional answer, the question becomes
  settled, unless the gap review of its cluster objects. A question
  where two families disagree stays open.
- **Observing class properties.** Tests observe a class property only
  through behavior, such as a deleted union member or a requires
  expression. Compiler builtin queries may serve as Evidence in a
  writer's probes, and no test uses them.
- **Library names.** The launder operation, `typeid`, and the bit copy
  stay referenced. Tests use no standard header. Q-0322 records the
  options.

Scope stays as the charter says. Coroutines, modules, threads and the
memory model, extended floating-point types, the preprocessor beyond
`#include "file"`, the general library, and MSVC stay out. Language
versions after C++23 stay out (Q-0007).

## Consequences

- `documentation/roadmap.md` gains a phase 6 table, and
  `documentation/status.md` points its next steps at it.
- Each phase 6 commit that settles questions states how many were
  opened and closed.
- Item O's method controls follow decision 0044.
