The 26 `planned` rows of phase 11 now name F2, or T and FE
(`reports/clean-room/ledger.md`).

These choices hold until the maintainer decides otherwise:

- **A `planned` row names a live item.** When an item ends, the
  closing commit lists its `planned` rows and moves each to an item of
  the next phase or to `open`. A row deferred for want of a probe
  carries the probe's path when it moves again.
- **A front-end finding gets a test in the commit that records it.**
  The front-end harness sees only tests. Port programs become program
  tests, as Write programs do.
- **A front-end round runs in each phase that changes rules.**
- **Review points get IDs and ledger rows.** A gap review gives each
  point an ID such as `RV5-A-3`, and a point that the repair commit
  leaves gets a `planned` row.
- **A commit follows a passing chain.** `tools/checks.py > FILE &&
  git commit` is the chain. A commit whose check fails waits for the
  fix.
- **The share comes from a tool.** The closing commit copies the line
  that `question_index.py` prints, and compares it with the previous
  phase's line.
- The choices of decisions 0051, 0054, 0055, 0056, 0057, and 0058 stay.

Propose X24 on P26 with refresh notes for X9, X14, X21, X22, and X23,
