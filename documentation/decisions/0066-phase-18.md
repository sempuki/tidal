## Context

Phases 1 to 17 are done, except that build step 3 of the rewrite is
done in part. Five clean-room views ranked what comes next
(`reports/clean-room/roadmap-15/`): a programmer, an implementer, an
editor, a clean-room writer, and a language designer. They agree on
these points:

- The new front end owns 1327 tests through the takeover list, but the
  checks do not hold them. `conformance.tsv`, the "0 worse" line, and
  the completion line still read the old front end's status, only
  `tools/frontend_check.py --next` runs the owned tests on the new front
  end, and `tools/check_all.sh` runs the tool without `--next`.
- Build step 3 passes 1602 of the 1897 plain tests (the old front end
  1892). Where a test uses a construct of a later step, the new front end
  often gives a rejection or a stop for undefined behavior where it
  should give `unsupported` (decision 0060): 113 false rejects over all
  tests, and 21 valid program tests rejected. It also runs three
  programs with undefined behavior to 0. Left in the step: 122 missing
  checks, the first error of 185 passing rejects, linking several units,
  `long double`, and the byte view. Lambdas need classes and move to
  build step 4.
- 13 exercise ledger rows are `open`: X26-1 to X26-6, RV11-R-1 to
  RV11-R-3, RV11-R-5, RV11-R-7, RV11-R-8, and F7-2. RV11-R-1 comes first:
  TPL-4 now rejects a valid friend form. The writer's round 15 probes
  confirm every host-only claim of X26, find every compiler agreeing on
  G182 (a union partial specialization) and G183 (LIST-4 and a
  conversion to the member's class), and find four splits that need
  questions or table rows.
- The programmer's reductions show 7 faults of the old front end with
  no test, 5 of them new in kind.
- The prototype hook has three gaps that X26 found (a node check does
  not see an unevaluated operand; no class for a result at
  substitution; no point that removes an alternative or checks a
  declaration), and X24's 19 prototype tests have no directory.
- A narrow second review of the questions held only by a doubt has
  waited for seven phases. 44 questions wait for "a review (doubt)" and
  nothing else.
- Review point IDs collide: RV10-n sits beside RV10-R-n, and RV11-R-n
  is taken by the read of RV10's repair diff.

The 13 `open` rows of the exercise ledger now name item F8
(`reports/clean-room/ledger.md`). The front-end rows G182 and G183 stay
`open` and name item GR2.

These choices hold until the maintainer decides otherwise:

- **Owned tests take the new front end's status** once item TK lands.
  The old front end stays the front end of record for every other test.
- **The rewrite says `unsupported` for a construct of a later step.** A
  rejection or a stop for undefined behavior from the new front end
  names a rule of a step it has built.
- **Review point IDs take a distinct form for each review.** A gap
  review uses RV12-n, its repair read RV12-R-n, and the next review
  RV13; the ledger header names each form.
- The choices of decisions 0051, 0054, 0055, 0056, 0057, 0058, 0059,
  0061, 0062, 0063, 0064, and 0065 stay.

Principle sentences and a use batch for the questions that wait for
one, Implement I8 on instantiation, Port suite P5, guides, refresh
notes for the done designs, an index of what a test of validity can
see, reject tests that pass on a grammar error, and first tries in the
completion count wait for a later phase. Later versions stay out of
