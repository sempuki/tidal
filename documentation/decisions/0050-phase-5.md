# 0050. Phase 5: consolidate, fill the object model, exercise

Date: 2026-10-31
Status: Provisional. Extends 0033 and 0039. The maintainer can reorder
or drop any item.

## Context

Phases 1 to 4 of the roadmap are drafted. Five clean-room views ranked
what comes next (`reports/clean-room/roadmap-2/`): a programmer, an
implementer, an editor, a clean-room writer, and a language designer.
They agree on these points:

- The specification has grown faster than its consolidation. 270
  questions are open, and several clusters state one model in drifting
  words: constraints as a tie-breaker (OVL-19, OVL-30, OVL-41, ORD-13),
  braced lists for references and arrays (15 questions), and "must an
  implementation diagnose" (16 questions). Some questions duplicate
  others, and some are moot after phase 4.
- Ordinary generic code still stops at objects built in raw storage:
  placement `new`, arithmetic over storage from an allocation function,
  reuse of storage, and object representation.
- The one-definition rule does not name templates.
- The new template pages have many rules with one test and many tests
  that no rule cites.
- Coroutines, the preprocessor beyond `#include "file"`, lexical
  structure, extended floating-point types, and the general library
  stay out.

## Decision

Phase 5 has these items, in this order. Items in one row can run in
parallel.

| Item | Work | Source views |
|---|---|---|
| T0 | Close phase 4: the gap-review repairs of R and P, and front-end round 8 | all |
| C1 | Consolidate question clusters: one constraint tie-breaker model, the braced-list cluster, the "must diagnose" cluster; merge duplicates and close moot questions | editor, writer |
| C2 | Thicken the templates chapter: a second test for single-test rules, and rules that cite every template test | editor, writer |
| F1 | Objects in raw storage: placement `new`, storage arithmetic, reuse, object representation (a new Foundations page) | programmer, implementer |
| F2 | Language-support types, round 2: the placement and aligned allocation forms, and the shapes of the exceptions the language throws (extends decision 0041) | programmer, implementer, writer |
| F3 | Templates across translation units on `odr.md` | programmer |
| L | Lanes U, V, and X of the roadmap: settle the arithmetic and comparison pages, thicken thin pages, digest the overrides | writer, editor |
| E | Exercises: Write suites for generic code, Predict batches for the template pages, a Diagnose batch on missed rejects, Propose round 2 (X5 to X8) | programmer, designer, implementer |
| FE | Front end: templates in the interpreter, run outcomes in the regression baseline, a `run-fail` test for every `undefined` rule | implementer |

Scope stays as the charter says. Coroutines, the preprocessor beyond
`#include "file"`, lexical structure beyond G1, extended floating-point
types, and the general library stay out. The deferred class-property
lists (items S and T) wait for a decision on how to observe a property
that only the library names.

## Consequences

- `documentation/roadmap.md` gains a phase 5 table, and
  `documentation/status.md` points its next steps at it.
- Items F1 and F2 change the charter only by extending decision 0041.
  Each needs a source-reader inventory first (method controls).
